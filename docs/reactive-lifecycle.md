# Guarded reactive lifecycle

The reactive DnD streams are hot event surfaces, but event order is not arbitrary. Every runtime now exposes the same stateful lifecycle guard.

## Strict lifecycle

The default mode is strict:

```text
idle
  -> drag-start
  -> (drag-enter | drag-over | drag-leave)*
  -> drop?
  -> drag-end
  -> idle
```

Rules:

- `drag-enter`, `drag-over`, `drag-leave`, `drop`, and `drag-end` require an active `drag-start`;
- a new `drag-start` cannot replace an active drag;
- the drag ID cannot change before `drag-end`;
- after `drop`, the only accepted lifecycle event is `drag-end`;
- `drag-end` may occur before `drop` for a canceled drag;
- an optional reactive operation must be allowed by the source envelope;
- an optional target ID must be non-empty.

Invalid transitions fail before an event is published to the hot stream or replayable state.

## External one-shot drops

OS/browser drags can enter the application without a source-side `drag-start` generated by ores-dnd. Hosts that need this use `external-drop-compatible` / `ExternalDropCompatible` mode.

In that mode an idle `drop` is accepted as a one-shot terminal event. It does **not** make replayable state active and does not create a synthetic ongoing drag. All other idle non-`drag-start` phases remain invalid.

## Runtime surfaces

- TypeScript: `DndLifecycleGuard`; `OresDndReactiveBus` accepts `lifecycleMode` and defaults to `strict`.
- Dart: `DndLifecycleGuard`; `OresDndReactiveBus` accepts `lifecycleMode` and defaults to `strict`.
- Rust: `DndLifecycleGuard` plus `guarded_next` for `DndLocalEventSubject`.

Rust's `DndReactiveEvent::new` remains the event-local validation boundary for source-allowed operations and non-empty targets; `DndLifecycleGuard` adds cross-event ordering.

## Backpressure

Only high-frequency presentation derivatives such as `drag-over` may be sampled/coalesced. The canonical guarded stream must retain `drag-start`, `drop`, `drag-end`, transition errors, and accepted-drop effect receipts. Do not place a lossy debounce/throttle between the lifecycle guard and terminal effect handling.
