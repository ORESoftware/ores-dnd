# ores-dnd

`ores-dnd` is the fleet-wide drag-and-drop contract and adapter library for browser/webview TypeScript, Rust desktop/WASM, portable WASM consumers, and Dart/Flutter.

The goal is not a single UI widget. The goal is one long-lived protocol for drag payloads, copy/move/link negotiation, drop results, persistence hooks, telemetry, and functional-reactive lifecycle streams across runtimes so each application can keep native UI while sharing semantics.

## Contract authorities

`contracts/main.tsp` and `contracts/authored.schema.json` are independent, human-authored peer authorities. `@oresoftware/typespec-json-schema-validator` (`tjsv`) generates a comparison witness only and fails closed when the authorities or instance corpus diverge.

```bash
npm install
npm run contracts:check
```

Generated validator output belongs under `.typespec-json-schema-validator/generated/` and is evidence, never a third authored authority.

The contract also carries the drag *session* semantics: `DndDropPolicy` (what a target accepts), `DndSessionInput` → `DndSessionSnapshot` (the state machine every runtime implements) and `DndSessionTrace` (executable conformance traces under `contracts/instances/DndSessionTrace/valid/`, generated by `scripts/gen-traces.py`). See [`docs/DESIGN.md`](docs/DESIGN.md) for the full design.

## Runtime targets

| Target | Path | Intended consumers |
| --- | --- | --- |
| TypeScript + DOM/WebView (`@oresoftware/ores-dnd`) | `src/ts` | `*-web-server.rs` HTML/HTMX/webviews and JS clients: codec, policy, session, HTML5 DnD + pointer fallback, htmx commit, external browser drops, keyboard adapter, WASM shim |
| Rust core (`ores-dnd-core`) | `src/rust` | shared `*-pub-lib-core`; codec, drop policy, session state machine, ports |
| Native Rust bridge (`ores-dnd-native`) | `src/rust-native` | `*-desktop-app.rs` hosts built with GPUI, Slint, Qt/QML FFI, winit/tao or similar: normalize native callbacks into the canonical session without owning OS file/temp/clipboard resources |
| Rust → WASM (`ores-dnd-wasm`) | `src/rust-wasm` + `wit/` | JS clients, Flutter web bridges, Rust desktop webviews; JSON-string ABI incl. `WasmDndSession` |
| MASH (`ores-dnd-mash`) | `src/rust-mash` | maud drop-zone/drag-source markup, htmx wiring, axum drop-commit endpoint that re-verifies every drop server-side |
| Leptos (`ores-dnd-leptos`) | `src/rust-leptos` | Leptos 0.8 islands/CSR: session signal, `DropZone`/`DragSource`, `web_sys` DataTransfer glue |
| Dioxus (`ores-dnd-dioxus`) | `src/rust-dioxus` | Dioxus 0.7 web + desktop + mobile over the portable `DataTransfer` |
| Dart (`ores_dnd`) + Flutter (`ores_dnd_flutter`) | `src/dart`, `src/flutter` | `*-flutter` iOS/Android/desktop/web clients: pure-Dart core (codec, policy, session, conformance adapter) and `OresDndController` / `OresDraggable` / `OresDragTarget` widgets |

The browser MIME type is `application/vnd.ores.dnd+json`. Plain-text fallback is emitted only for text items.

## Functional-reactive streams

The three primary client runtimes expose native ReactiveX-style lifecycle surfaces:

- TypeScript: RxJS-backed typed surface at `@oresoftware/ores-dnd/reactive`.
- Dart/Flutter: RxDart surface at `package:ores_dnd/ores_dnd_reactive.dart`.
- Rust/WASM: rxRust surface at `ores_dnd_core::reactive`, with `Local` preferred for UI/WASM and `Shared` available for intentional cross-thread native flows.

Raw DnD events are hot and non-replaying because they may contain dragged payload data. Only metadata-only state may use replay/current-value semantics. Persistence and forms are still explicit accepted-drop effects; observing or transforming a stream never writes application state by itself.

See `docs/reactive.md` for lifecycle, privacy, throttling/backpressure, and subscription-ownership rules.

## Integrations

The core libraries intentionally use narrow ports instead of importing application state directly:

- `opto-sync`: persist accepted drop mutations to IndexedDB/SQLite and sync them through the app's existing data plane.
- `ores-forms`: map accepted drops into explicitly allowed form fields/actions.
- `ores-otel`: emit content-free lifecycle telemetry (phase, operation, item count, runtime, target), never dragged data or credentials.
- `zed-pkg`: publish/install `oresoftware/ores-dnd` as a multi-target dependency so `*-pub-lib-core` repos can expose the same semantics to web, desktop, and Flutter apps.

See `docs/integrations.md`, `docs/adoption.md` (the per-org runbook), `docs/native-desktop.md`, `examples/` (a MASH kanban app and a vanilla-DOM page) and `rollout/fleet.toml`.

## Security defaults

- Payloads are versioned and size-bounded before parsing.
- Unknown operations, item kinds, and protocol versions are rejected.
- Telemetry and replayable reactive state never contain item `data`.
- Raw envelope streams do not replay to late subscribers.
- External URI/file drops are data only; adapters never fetch/open URIs as a side effect of admission.
- The native bridge does not own local paths, file promises, temp-file cleanup, sandbox bookmarks, clipboard monitoring or platform share sheets; those remain explicit host responsibilities.
- Persistence and form application are opt-in ports; a decoded or emitted drop does not mutate storage by itself.
- Copy/move/link is negotiated against both source and target capabilities.

## Development

```bash
# TypeScript / RxJS
npm --prefix src/ts install
npm --prefix src/ts run build
npm --prefix src/ts test

# Rust (core incl. rxRust reactive, native bridge, wasm, mash, leptos, dioxus)
cargo test --workspace --all-features
cargo clippy --workspace --all-features --all-targets -- -D warnings
rustup target add wasm32-unknown-unknown
cargo check -p ores-dnd-wasm --target wasm32-unknown-unknown

# Dart (pure core incl. RxDart reactive) and Flutter (widgets)
(cd src/dart && dart pub get && dart analyze --fatal-infos && dart test)
(cd src/flutter && flutter pub get && flutter analyze && flutter test)
```

## Cross-runtime conformance

```bash
npm run conformance              # corpus → TypeScript, Rust and Dart adapters → tjsv verifier
npm run conformance -- --skip dart
```

`scripts/conformance/` turns the tjsv parity receipt into a Contract IR, runs the same 76-instance corpus through each language's decoder (`src/ts/conformance-adapter.mjs`, `cargo run --example conformance`, `dart run bin/conformance_adapter.dart`) and admits the evidence only when it names the exact IR id, parity run id and corpus digest and every adapter's verdicts match the declared expectations — a flipped verdict or a missing adapter stops the gate. The session traces (23 hand-written + 40 differential fuzz traces generated by the Rust core) are replayed separately by every language's own test suite, and each core runs thousands of seeded random sequences against the state-machine invariants.

CI runs contracts, typescript, rust (workspace + clippy, including the native bridge), wasm (check) and wasm-e2e (the compiled module against the corpus, the traces and 2000 random policy evaluations + 300 random sessions cross-checked with the TypeScript core), dart, flutter and the conformance gate; the conformance evidence is retained as a workflow artifact.
